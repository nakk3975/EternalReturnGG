# 성능 점검 — 2026-09-17

기준: main 09d1d3b. 서버 API/캐시/백그라운드 수집, 웹 요청·렌더링·동선·화면 인식, 데스크톱 IPC/렌더링 및 CI 구성을 점검했다. 아래는 이번에 수정하고 검증한 범위다. 모든 메뉴의 실서비스 응답 시간을 측정했다는 의미는 아니다.

## 수정

- 사냥 추천: 경로 탐색 안에서 반복하던 캠프 상태·개체 수 계산을 추천 1회당 캠프 1회로 제한. 호출 사이에는 캐시하지 않아 시간 변경·처치·제외를 즉시 반영한다.
- 오버레이: 수동 시계 정지 중 초당 전체 재계산/IPC/DOM 교체 제거. 동일 스냅샷 중복 전송 방지, 지도 지형 문자열 재사용, 지도 좌표가 같으면 설정 지도 DOM 유지.
- 화면 분석: 같은 해상도의 프레임마다 캔버스 크기를 재설정하던 작업 제거. 캡처/인식 주기와 정확도 판정은 유지.
- 서버 선조회: 작업 대기열 64개 제한, 동일 경로 중복 대기 제거, 이미 신선한 캐시가 있으면 생략. 포화 시 선택적 선조회만 생략하며 사용자 요청은 정상 처리한다. 사용되지 않는 경기 선조회 코드 제거.
- 수집기: 성공적으로 저장한 체크포인트와 상태가 같으면 반복 쓰기를 생략. 변경된 상태 및 실패한 쓰기의 재시도는 계속 저장한다. 일일 한도 도달 후 20초마다 발생하던 동일 DB 쓰기 제거.

## 검증 및 한계

- 기존 웹 회귀 검사와 캠프별 계산 횟수/수정 반영 검사.
- 오버레이 정지 시 IPC 생략, 동일 지도 DOM 보존, 추천/처치/초기화/팀 표시 검사.
- 서버 중복 선조회·포화 대기열, 수집기 동일 상태 쓰기 생략·실패 후 재시도 검사.
- Java 빌드, 실제 Chromium OCR, Windows 패키지 실행은 GitHub Actions에서 확인한다. 로컬은 Gradle 다운로드와 jsdom 설치가 준비되지 않아 해당 검사에 사용할 수 없다.
- Render 절전 후 첫 접속, 실제 게임 화면 CPU/FPS, Supabase SQL 실행계획은 이번 로컬 측정에 포함되지 않는다. 기존 API 대기시간과 게임 화면 인식 정확도까지 개선됐다고 주장하지 않는다.
