## 발견하고 수정한 오류

- 경기 응답 필드는 `coolDownReduction`인데 상세 빌드 화면이 `cooldownReduction`을 조회하고 있었다. 대소문자를 수정하고 실제 fixture 기반 회귀 검증을 추가했다. 아이템 메타데이터의 `cooldownReduction`은 별도 필드이므로 변경하지 않았다.
- WeaponTypeInfo 실제 응답은 `{type, attackRange, attackSpeed, shopFilter}`이며 `code`가 없다. 배열 순서를 숫자 ID로 추정하지 않는다. 공통 호환 ID 연결에 API type/로컬라이징을 결합하고, 새로운 문자열 type도 등록한다.
- API 메타데이터 조회 실패는 정상으로 가장하지 않고 호환 표시로 복구한다. 일부 숫자 ID(과거 무기군)는 현재 테이블에 없어도 과거 전적 표시를 위해 보존한다.

## 계약의 의미와 한계

`contracts/*.json`은 2026-09-14 실제 관측 타입을 기록한 회귀 계약이며 공식 명세가 아니다. 경기 구조에 필요한 8필드(gameId, characterNum, gameRank, matchingMode, matchingTeamMode, teamNumber, seasonId, startDtm)를 필수로 선택했다. 나머지는 미제공 시 화면에서 — 를 표시할 수 있는 선택 필드다. 값이 존재하면서 타입이 다르면 실패한다. 새로운 미지정 필드는 허용한다.

Object/Array의 내부 의미까지 보장하지 않는다. 특히 사망 위치·개별 처치 로그, 크레딧 소스, 큐브/LUMI, 과거 모드 필드는 추가 실제 표본이 필요하다. 랭킹·시즌 통계·추천 루트·지역 드롭 전체 계약 검증도 별도 남아 있다. `skillAmp`, `tacticalSkillUseCount` 등 이 표본에 없는 선택 필드는 값을 만들어 넣지 않는다.

## 재현

오프라인 실제 fixture + 기존 회귀 테스트:

```sh
node --test src/test/js/*.test.cjs
```

결과: 13개 test 파일 PASS. Java `gradlew test --offline`은 Gradle 8.5 미설치 및 다운로드 네트워크 제한으로 실행하지 못했다. Render 첫 변경 배포(794ec93)는 빌드·기동 후 live 상태 확인. Docker 빌드를 Java 단위 테스트 통과로 간주하지 않는다.

실제 공식 API 직접 검사:

```sh
# ETERNAL_RETURN_API_KEY는 비밀 환경변수로 설정
ER_VERIFY_NICKNAME=hoyoung node scripts/verify-live.cjs
```

배포 서버 경유 검사:

```sh
ER_VERIFY_BASE_URL=https://eternalreturngg.onrender.com ER_VERIFY_NICKNAME=hoyoung node scripts/verify-live.cjs
```

`live-verification.json`에 성공/실패와 선택 필드 누락을 기록한다. 닉네임, userId, API Key, 전체 응답은 보고서에 넣지 않는다. 요청은 순차로 최소 1.1초 간격이며 45초 timeout을 둔다. 이 스크립트 자체의 외부 실행은 이 환경에서 수행하지 않았다. 위 운영 검증은 브라우저에서 동일 endpoint를 열어 검사한 결과다.

GitHub Actions `API contracts`는 push/PR에서 JS 및 Java 검사를 실행한다. 수동 실행에 nickname을 입력하면 저장소 Secret `ETERNAL_RETURN_API_KEY`로 직접 API를 검사하고 보고서를 artifact로 보관한다. Secret은 이번 작업에서 새로 등록하거나 복사하지 않았다. 미설정 상태를 성공으로 처리하지 않는다.

## 이슈 종료 판단

이번에 실제 데이터 회귀 검증과 운영 검색 검증 증거는 추가했지만, 네 항목 전체 완료 조건은 아직 충족하지 않았다. 숫자 ID 연결 완전 대체, 전체 화면·모드·시즌의 계약, 전 신규 에셋 검증, 캐시 없는 직접 Key 실행이 남아 있으므로 이슈를 닫지 않는다.
